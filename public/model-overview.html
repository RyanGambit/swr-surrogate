Layer 1 — Data gathering
3–5 minutes
Address lookup
User enters a street address. Scout auto-populates building type, year built, size, climate zone, LDC, and satellite view using public data sources.
Baseline archetypes
Building type + vintage → default HVAC system, wall construction, insulation R-values, window type, air tightness, and equipment lifecycle estimates.
User input
Ownership model, role, motivations, investment approach, annual energy cost, and the business operating in the building.
Ryan / Gambit Address search engine (Nominatim, OSM, MPAC)
Antoni / WSP Baseline spreadsheet — archetype data by building type + vintage
Pratik / SWR LDC mapping, Ontario energy rates, incentive program database
Assessment object
Structured building profile with confidence scores — building, envelope, systems, energy, context, user, and per-field confidence rating
Layer 2 — Conversational enrichment
Optional · 2–3 minutes
Scout conversation
Scout asks 3–5 targeted questions about low-confidence parameters only. Users can skip this step and go straight to results with current data.
One master prompt — not separate prompts per page. Chat carries full history and is available on the dashboard as a side panel.

Deterministic calculations

Step C — Hero selection
The user's stated approach (from intake) determines which pathway is highlighted as the primary recommendation. All three are always shown.
"Fix what's urgent"
→
Essential is the hero
"Invest if strong case"
→
Targeted is the hero
"Full opportunity"
→
Deep retrofit is the hero
"Figuring it out"
→
No hero — show all three equally
MCDA criteria weights (cost, payback, GHG, incentive capture, disruption risk, regulatory compliance, asset uplift) shift automatically based on approach. Weights are hard-coded per approach type — not AI-determined.
The deliverable — what the user walks away with
Downloadable package
Scout action plan
Phased retrofit roadmap framed for the user's ownership type and selected pathway. This is what they take to their board, CFO, or asset manager. The plan is the product — not the dashboard.
Every output is pathway-specific. The business case for "Essential" has different numbers, different framing, and different incentive references than the business case for "Deep retrofit." Documents are generated from the selected pathway's model outputs — not generic templates.
Every output is ownership-specific. An asset manager sees NAV impact and NOI improvement. A condo board sees reserve fund impact and special assessment avoidance. Same pathway, different financial language.

Key design principles: Every number is traceable — not AI-hallucinated. Scenarios are deterministic. Static data (incentives, building code, rates) is cached and refreshed quarterly — not searched live every session. The tool speaks different financial languages to different ownership types (landlord vs. asset manager vs. condo board). Outputs are the product — if the user leaves with only knowledge and no artifact, we've failed.
